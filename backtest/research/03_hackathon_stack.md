# Research 3 - BNB Hack Tokenized Stocks Edition: competitive and technical intelligence

*Compiled 26 Sep 2026 by a research agent (~40 pages fetched). Every URL in section (f).*

## (a) API capability map for a weekly-settled gap-insurance vault

**Auth (all `web3.binance.com/build` endpoints).** Headers `X-OC-APIKEY`, `X-OC-TIMESTAMP` (ISO-8601 ms, e.g. `2026-05-11T10:08:57.715Z`), `X-OC-SIGN` = `Base64(HMAC-SHA256(timestamp + method + requestPath + body, secret))`, optional `X-OC-RECV-WINDOW` (default 5000, max 60000) and `X-OC-NONCE`. **Gotcha 1:** `requestPath` must include the `/build` prefix and the exact raw URL-encoded query string, or you get `40102`. Limits: 1,200 req/60s per IP and per key, 6,000 per user, **5 RPS per endpoint default**; 429 with `Retry-After`. Keys come from https://web3.binance.com/en/dev-portal ; the hackathon registration form asks for the Binance UID tied to the key so limits can be raised. **Gotcha 2:** IP checks are enforced "on both the Developer Portal and the API server side" for US/CA/NL/UK/JP etc.; Portir's README reports buys are "quoted-only from non-cloud networks due to Binance API compliance restrictions": pick the keeper-agent hosting region deliberately and test from it on day one.

**RWA Data API (signed, Market API family).** Six endpoints, all GET:
`/api/v1/dex/market/rwa/platforms` (issuance platforms; call first to enumerate real `platformId` values), `/api/v1/dex/market/rwa/price` ("batch query RWA token prices, including on-chain price and underlying reference price"), `/api/v1/dex/market/rwa/search`, `/api/v1/dex/market/rwa/underlying-profile`, `/api/v1/dex/market/rwa/tokens` ("supports filtering by platform and sector tab"), `/api/v1/dex/market/rwa/underlying-market`. Per-endpoint parameter tables were not retrievable as Markdown, so read them in the dev-portal reference UI; competitor repos confirm multi-issuer coverage (Assay: "667 tokenized equity tokens covering 512 tickers"; Closing Bell: 488 candidates scanned on BSC).

**Public RWA endpoints (no key; what the `binance-tokenized-securities-info` skill and most competitors use).** Base `https://www.binance.com/bapi/defi/`; send `User-Agent: binance-web3/1.1 (Skill)` and `Accept-Encoding: identity`:
- `v1/public/wallet-direct/buw/wallet/market/token/rwa/stock/detail/list/ai?type=1` : token list; `type=1` = Ondo. Returns `chainId`, `contractAddress`, `multiplier`. (Our own pull found type=2 xStocks, type=3 bStocks also returned.)
- `.../rwa/meta/ai?chainId=56&contractAddress=` : CEO/industry/attestation PDFs (prepend `https://bin.bnbstatic.com`).
- `.../rwa/market/status/ai` : market-wide `openState`, `reasonCode`, `reasonMsg`, `nextOpen`/`nextClose` (ISO) and `nextOpenTime`/`nextCloseTime` (ms). Sample shows `MARKET_PAUSED`, "Paused for session transition".
- `.../rwa/asset/market/status/ai?chainId&contractAddress` : per-asset `openState`, `marketStatus` in {`premarket`,`regular`,`postmarket`,`overnight`,`closed`,`pause`}, `reasonCode` in {`TRADING`,`MARKET_CLOSED`,`MARKET_PAUSED`,`ASSET_PAUSED`,`ASSET_LIMITED`,`UNSUPPORTED`,`MARKET_MAINTENANCE`}, `reasonMsg` in {`cash_dividend`,`stock_dividend`,`stock_split`,`merger`,`acquisition`,`spinoff`,`maintenance`,`corporate action`,`earnings`}.
- `v2/public/wallet-direct/buw/wallet/market/token/rwa/dynamic/ai?chainId&contractAddress` : `tokenInfo.price` (per token), `tokenInfo.sharesMultiplier`, `totalHolders`, `stockInfo.price` (**"May be `null` outside trading hours"**), 52w hi/lo, P/E, `statusInfo`, `limitInfo.maxAttestationCount`, `limitInfo.maxActiveNotionalValue` (e.g. "450000").
- `v1/public/wallet-direct/buw/wallet/dex/market/token/kline/ai?chainId&contractAddress&interval=1d&limit=300` : OHLC 1m to 1d. (Our pull returned only 2 candles per token: log it in the DX report.)

**Critical formula:** `referencePrice = tokenInfo.price / sharesMultiplier`. The multiplier drifts with reinvested dividends and jumps on splits (bStocks use BEP-677 "scaled UI amounts"). **For our payoff, snapshot `sharesMultiplier` at both Friday bind and Monday settle, and settle per-share, not per-token**; a weekend `ASSET_PAUSED/cash_dividend` should void or adjust the policy. **Gotcha 3:** `stockInfo.price` being null off-hours means "Monday-open reference price" must be defined as *the first non-null underlying print at or after `nextOpenTime`*, with a grace-window fallback (exactly how AfterHours defines it). `tokenInfo.volume24h` is US-stock volume, not on-chain volume.

**Trading API.** `GET /api/v1/dex/aggregator/quote` -> `executionMode` (`SWAP`|`RFQ`), `quoteId` (TTL 30 s, else `40401`), `vendorName`, `rfq.typedDataToSign`; `GET /api/v1/dex/aggregator/swap` (`slippagePercent` or `autoSlippage=true`); `GET /api/v1/dex/aggregator/quote-and-swap?vendor=LiquidMesh` (flash path); `GET /api/v1/dex/aggregator/approve-transaction` (`vendor` required for equity tokens); `POST /api/v1/dex/aggregator/order/submit` (`userSignature`, `vendor`, `quoteId`=`rfq.orderId`, `requestId` UUID for idempotency); `GET /api/v1/dex/aggregator/order/{orderId}` -> `FILLED`/`FAILED`; `GET /api/v1/dex/aggregator/history`. Routing by token type: **Ondo (type=1) = 3-vendor RFQ only** (InchFusion + CowSwap + PcsXRfq), **bStocks (type=3) = LiquidMesh SWAP + PcsXRfq RFQ mixed**, **xStocks (type=2) = AMM SWAP only**. Market-hours errors: `40367` (Ondo), `40369` (bStock): "may be unavailable outside US market hours". RFQ routes ignore custom fee params; SWAP routes support `feePercent` (0,5] with `feeSource=FROM_TOKEN|TO_TOKEN` (a revenue hook for the vault). MEV protection is `enableMevProtection` on `POST /api/v1/dex/pre-transaction/broadcast-transaction` (EVM-only private mempool). Ondo minimum orders exceed $5.

**Implication:** bStocks are the natural insured asset: they actually trade 24/7 on LiquidMesh while the underlying is shut; Ondo tokens are RFQ-only and likely `MARKET_CLOSED` all weekend, so an Ondo holder is *locked in* and cannot self-hedge, which is a second, different pitch ("you can't sell; buy cover instead").

**Transaction API.** `GET /api/v1/dex/pre-transaction/gas-price`, `GET .../block-height`, `POST .../gas-limit`, `POST .../simulate`, `POST .../broadcast-transaction`. Organisers: "dry-run with the Transaction API while you build, then demo with small live amounts": put simulate in the demo path and log its output.

**Wallet API.** `GET /api/v1/dex/balance/all-token-balances-by-address`, `POST /api/v1/dex/balance/token-balances-by-address`, `GET /api/v1/dex/post-transaction/transactions-by-address`, `GET /api/v1/dex/post-transaction/transaction-detail-by-txhash`.

**DeFi API (BSC only, 5 QPS shared).** Data: `POST /api/v1/defi/data/{position/list, protocol/list, protocol/detail, investment/list, investment/detail}`. Build: `POST /api/v1/defi/transaction/{deposit, redeem, lp-add, lp-add/calculate, lp-remove, claim}` returning unsigned `dataList` (approval steps then action), `simulate=true` gives a `preview`; APY as `apyBps`/`apyDisplay`. Protocols with deposit/redeem: **Venus, Venus Flux, Lista DAO, Aave V3, Aster, Solv** (+ Uniswap V3/V4, PancakeSwap V3/Infinity for LP). **No Ondo USDY/OUSG, no stablecoin vaults beyond lending.** Use: park idle Keeper-pool USDT in Venus between Friday bind and Monday settle; that is the yield leg with zero custom integration.

**b402.** `POST /api/v2/b402/supported|verify|settle` (v1 retained). BSC `eip155:56`, EIP-3009 and Permit2, facilitator-sponsored gas; asset list is config-driven (read `/supported`). The Agentic Wallet has `baw x402-payment preview` / `sign` (x402 **v2 only**, USDT on `56`, returns `PAYMENT-SIGNATURE` header, `BLOCKED_DAILY_LIMIT_REACHED` possible). This is a premium-collection rail that needs no approve/transfer UX.

## (b) Agentic Wallet, Wallet Skills, Agent Studio: what wins the two $2k specials

**What the AI execution layer is.** `npx skills add binance/binance-skills-hub/skills/binance-web3/binance-agentic-wallet` installs the `baw` CLI (skill v1.12.0). MPC keyless wallet created in the Binance App; sign-in via QR (`auth signin/verify/signout`). **Mainnet only; no testnet/sandbox exists**; chains BSC, ETH, Base, Solana. Security rules (daily limit, token scope, high-risk auto-reject vs confirm, Developer Mode) are **only settable in the Binance App**; the agent can read them (`baw wallet settings --json`). Reference files: `approvals.md, authentication.md, defi.md, external-sign.md, gas.md, limit-order.md, market-order.md, prediction.md, preflight.md, security.md, send.md, speedup-cancel.md, wallet-setting.md, wallet-view.md, x402-payment.md`.

The two commands that make a credible insurance flow possible are in `external-sign.md` (Developer Mode required):
- `baw contract-call preview --binanceChainId 56 --from <agentWallet> --to <vault> --value 0 --inputData 0x... --json` -> simulation + risk result + `requestId`; then `baw contract-call execute --requestId ...`. If `requireConfirmation=true` the execute creates an order the human must approve in the Binance App.
- `baw sign-message preview --signType EIP712 --message '{"method":"eth_signTypedData_v4","params":[addr, typedDataJson]}'` -> `sign-message execute`. This is what signing `rfq.typedDataToSign` for a bStock/Ondo RFQ needs, and what a Permit2/EIP-3009 premium payment needs.

Plus `market-order quote|swap`, `limit-order buy|sell` (BSC/Solana), DeFi deposit/redeem, `x402-payment`. Skill rules judges will look for: `--json` everywhere, confirm before state changes, never downgrade a conditional order, show full contract addresses, pre-check security.

**"Deepest, most credible use" for our product:**
1. Ship a **first-party skill** `weekend-cover` (SKILL.md + `references/*.md`) in our repo, installable with `npx skills add <org>/<repo>`; open a PR to `binance-skills-hub` (fork -> `skills/<name>/SKILL.md` with YAML frontmatter -> PR). Even an open PR is demonstrable.
2. Sleeper flow, entirely via skills: `binance-tokenized-securities-info` resolves NVDAB/TSLAB -> status check (`reasonCode`, `nextOpenTime`) -> our skill calls the quote API -> `baw contract-call preview/execute` to `buyCover()` (or `baw x402-payment sign` to pay the premium via b402) -> Monday: skill reads settlement and calls `claim()`.
3. Keeper flow: `baw market-order quote` on the bStock to prove on-chain liquidity, `baw defi deposit` idle USDT into Venus, `baw approvals list/revoke` hygiene at the end.
4. Guardrails mirroring the skill's own rules: preflight before every execute, show `requireConfirmation` state, honour daily-limit errors, no unattended loops on the human wallet.

**BNB Agent Studio.** `npm i -g @bnbagent/studio-cli` -> `bag skills install` -> `bag init` -> `bag wallet new` -> `bag dev` -> `bag erc8004 register --endpoint <URL>` -> `bag deploy --provider bnb|aws|azure`, `bag deploy verify`, `bag erc8183 list|status|settle`, `bag x402 quote|buy`, `bag budget enable`, `bag audit ls`, `bag mcp serve` (15 read-only tools). One runtime hosts three faces: A2A (agent card + JSON-RPC `:9000`), MCP (`:8000/mcp`), X402 (`/x402`, `price_usd>0` = B402 challenge settled before work). **The LLM never signs**: `signing.ts` is fixed code; prices clamped to `[min_price,max_price]` from `studio.toml`. ERC-8183 flow: buyer `negotiate` -> create job/budget/fund escrow -> `notify_funded` -> seller verifies terms on-chain -> `submit` deliverable -> buyer `approve|reject|dispute`. ERC-8004 identity: BSC mainnet `IdentityRegistry 0x8004A169FB4a3325136EB29fA0ceB6D2e539a432`, `ReputationRegistry 0x8004BAa17C55a88189AE136b182e5fdA19dE9b63`. **Runtime limit:** the `bnb` target is a "managed 48-hour testnet trial"; persistence needs AWS AgentCore in your own account. No cron primitive documented: implement the weekly cycle inside `sellerCore.ts`'s `runWork` with a poller.

**A persistent "Weekend Risk Agent" that judges will credit:** ERC-8004-registered seller with agent card advertising `x402Support`; free MCP tools (`quote_cover`, `gap_history`, `market_status`) and a paid `/x402` `bind_cover` that returns a signed quote (B402 settles the premium, gas-sponsored); ERC-8183 job for "monitor + settle my policy", where the evaluator is the settlement contract's first-print rule, so `complete()` is mechanical; Sleepers `giveFeedback()` on the Reputation Registry after payout. Run the same code on the 48h testnet trial for judges and on AgentCore for the mainnet demo. NightDesk and Portir already do reports-as-a-service at a shallower level; the differentiator is that our agent *underwrites and settles real risk*.

## (e) Open risks (rules and operations)

- **"Spot only. Perps are out."** Nothing official mentions options, insurance or structured products; the only positive signal is "cross-asset products are in scope" and press coverage of "new financial products unavailable in traditional markets". A cash-settled put is a derivative by economics. **Mitigation:** frame as *fully-collateralised gap cover attached to a spot position*, no leverage, no short exposure, principal-protected vault as the Keeper side; **ask in the builder Telegram this week and screenshot the answer** for the DX report.
- **Mainnet-only everything.** Agentic Wallet has no testnet; Studio's `bnb` trial dies after 48h; judging runs 12 days: deploy on AgentCore or self-host, keep the link alive through 23 Oct.
- **Weekend liquidity/tradability.** Ondo likely `MARKET_CLOSED` all weekend; bStock RFQ may 40369; LiquidMesh SWAP depth is thin. Settlement must not depend on any weekend trade.
- **Reference-price definition.** `stockInfo.price` null off-hours; use first non-null print >= `nextOpenTime`, multiplier re-read, void on `ASSET_PAUSED`.
- **Geo/IP.** Team and servers outside US/CA/NL/UK/JP; the jurisdiction disclaimer belongs in the UI.
- **Human-in-the-loop caps.** `requireConfirmation=true` may force Binance-App approval; keep demo amounts under the daily limit and show the approval in the video.
- **Doc gaps.** Signed RWA endpoint parameter tables not fetchable as Markdown: confirm `platformId` values via `/rwa/platforms` on day one and record the friction.
